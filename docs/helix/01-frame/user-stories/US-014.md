# US-014: Record time zone with every entry

**Feature**: FEAT-003 — Time Tracking
**Feature Requirements**: see FEAT-003
**PRD Requirements**: FR-22, FR-23, FR-24
**Priority**: P0

## Story

**As a** Priya, Member
**I want** to have my time zone saved with each entry
**So that** reports show when I worked in my local time and month ends are exact

## Context

Distributed staff log from different zones, and month-end totals must not shift because of UTC.

## Walkthrough

1. User signs in and the browser time zone is proposed as their profile zone
2. User confirms or changes it
3. User logs time
4. System stores the start instant, zone, offset, and local date
5. An entry crossing local midnight is split into two entries

## Acceptance Criteria

- [ ] **US-014-AC1** — Given a user with profile zone America/Chicago, when they log a timer starting 21:00 local, then the entry stores the UTC start, America/Chicago, the offset, and the local date
- [ ] **US-014-AC2** — Given a timer from 23:00 on 31 May to 01:00 on 1 June local time, when it is stopped, then two entries are saved, 60 minutes on 31 May and 60 minutes on 1 June, each in the entry time zone
- [ ] **US-014-AC3** — Given a user who changes their profile zone, when they view past entries, then past entries keep their recorded zone

## Edge Cases

- Daylight-saving change during an entry: duration is elapsed time.
- Manual entry with no start time: zone and local date stored, start time of day empty.
