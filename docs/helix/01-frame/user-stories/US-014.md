# US-014: Import Everhour history

**Feature**: FEAT-007 — Everhour Import
**Feature Requirements**: see FEAT-007
**PRD Requirements**: FR-22, FR-23
**Priority**: P1

## Story

**As a** Alex, Admin
**I want** to import Everhour CSV exports with a preview
**So that** history moves over safely

## Context

Importing is the last step before retiring Everhour.

## Walkthrough

1. Admin uploads the CSV exports
2. System shows a dry-run summary with unmatched rows
3. Admin commits
4. System stores approved, locked entries

## Acceptance Criteria

- [ ] **US-014-AC1** — Given valid Everhour CSVs, when an Admin runs a dry run, then counts of projects, users, tasks, and entries show with unmatched rows listed and nothing is saved
- [ ] **US-014-AC2** — Given a committed import, when the same files are imported again, then no duplicate entries are created
- [ ] **US-014-AC3** — Given imported entries, when a user views them, then they are approved and read-only

## Edge Cases

- Unmatched email: row skipped and reported.
