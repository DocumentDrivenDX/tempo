# US-010: Approve or reject time

**Feature**: FEAT-005 — Entry Approval
**Feature Requirements**: see FEAT-005
**PRD Requirements**: FR-16, FR-18
**Priority**: P0

## Story

**As a** Marcus, Project Manager
**I want** to approve or reject my project's entries
**So that** only validated hours count

## Context

Approval happens per entry, so each project's managers approve only their own project's entries.

## Walkthrough

1. Manager opens the approval queue
2. Manager reviews pending entries for their project
3. Manager approves or rejects with a comment
4. System records the action

## Acceptance Criteria

- [ ] **US-010-AC1** — Given pending entries on projects A and B, when the Manager of A approves A's entries, then only A's entries lock and B's stay pending
- [ ] **US-010-AC2** — Given a Manager rejecting an entry, when they add a comment, then the entry returns to editable and the comment shows to the user
- [ ] **US-010-AC3** — Given any approval action, when it completes, then the audit trail records actor, time, and comment
- [ ] **US-010-AC4** — Given a Manager with their own pending entries on a project they manage, when they approve them, then the entries lock and the audit trail records a self-approval

## Edge Cases

- Manager bulk-approves a filtered set: each entry is approved and audited individually.
