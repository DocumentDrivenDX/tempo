# US-011: Reopen approved time

**Feature**: FEAT-005 — Entry Approval
**Feature Requirements**: see FEAT-005
**PRD Requirements**: FR-17
**Priority**: P0

## Story

**As a** Alex, Admin
**I want** to reopen an approved entry
**So that** mistakes found later can be corrected

## Context

Locking must have an escape hatch that leaves a record.

## Walkthrough

1. Admin finds a locked entry
2. Admin reopens with a reason
3. Entry becomes editable
4. Audit trail records it

## Acceptance Criteria

- [ ] **US-011-AC1** — Given an approved entry, when an Admin reopens it with a reason, then it becomes editable and the audit trail records the reopening
- [ ] **US-011-AC2** — Given a Member, when they try to reopen an approved entry, then the action is denied

## Edge Cases

- A reopened entry becomes pending again.

## Test Scenarios

| Scenario | AC ID | Input / State | Action | Expected Result |
|----------|-------|---------------|--------|-----------------|
| Happy path | US-011-AC1 | an approved entry | an Admin reopens it with a reason | it becomes editable and the audit trail records the reopening |
| Case 2 | US-011-AC2 | a Member | they try to reopen an approved entry | the action is denied |
